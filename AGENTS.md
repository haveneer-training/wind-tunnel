# AGENTS.md

Bootstrap for any coding agent (Claude Code included). It says what the repo is, how to
build and check it, and which rules are easy to break. The authority on project state,
conventions and their rationale is **`docs/AVANCEMENT.md`** (French): read it before any
non-trivial change. This file only points to it and does not repeat it.

## What this is

"Soufflerie numérique" (numerical wind tunnel) is the fil rouge project of a 3-day
training, « Découverte du langage Rust pour le calcul scientifique ». The audience is
C/C++ developers. The project is a finite-volume solver on an unstructured mesh:

- it reads an ASCII domain mask (`.` fluid, `#` solid, `%` comment);
- it builds a mixed triangle/quad mesh, with 45° chamfers where perpendicular walls meet;
- it advects a passive tracer around an obstacle;
- it writes VTK and PNG frames.

**This repo is the corrigé (reference solution).** `cargo xtask start` derives the
trainee's `travail/` from it, with the exercise blocks punched out as holes. `travail/`
is gitignored and excluded from the workspace: it is a standalone project.

## Architecture

```
mask ──▶ mesh ──▶ field ──▶ solver ──▶ io (VTK / PNG)
                    ▲          ▲
               velocity      flux
```

| Module | Role |
|---|---|
| `geom` | points, vectors, areas, centroids |
| `mask` | mask parsing and validation |
| `mesh` | cells, faces, connectivity, with typed indices (`CellId`, `FaceId`, `VertexId`) and `Side` |
| `field` | a scalar field over cells |
| `velocity` | analytic flows (uniform, potential cylinder) and the `StreamSource` trait that the solver consumes |
| `stream` | the computed flow (step 12): `∇²ψ = 0` at the vertices, dual-mesh weights stored in CSR, Jacobi |
| `flux`, `gradient` | the `FluxScheme` trait (`Upwind`, `Centered`, `Muscl`), and a least-squares gradient with a Barth–Jespersen limiter (step 7) |
| `solver` | time loop in *gather* form, CFL, boundary conditions, `--max-steps`/`--max-time`/`--every-dt` |
| `io/` | VTK (`write_dataset`, `write_frame`, `write_series`) and PNG output |
| `error` | two error families: mesh-time and solver-time |
| `app` | CLI and case assembly, shared by both binaries |
| `decomposition` | vertical bands for MPI (step 11) |

## Commands

```shell
cargo test                                   # root crate only; filter: --test step2_mesh, or a test name
cargo clippy --workspace --exclude wind-tunnel-mpi --all-targets --all-features --no-deps -- -D warnings
cargo fmt --all
cargo run --release -- domains/tunnel.dom --refine 4 --bands 9 --max-steps 960
cargo run --release -- domains/square.dom --flow computed      # the step-12 demo
cargo test -p xtask && cargo test -p wind-tunnel-design
cargo test --manifest-path solutions/Cargo.toml
cargo build --release -p wind-tunnel-mpi && mpirun -n 4 target/release/wind-tunnel-mpi domains/tunnel.dom
```

`cargo xtask` is an alias defined in `.cargo/config.toml`. Where each command runs:

- **from the repo root:** `start [--force] [--dir <p>]` creates `travail/`; `update [--dir <p>]`
  syncs corrigé changes into it and keeps the answers, matching each hole by step, scope
  and rank;
- **from `travail/`:** `status`, `next`, `goto <n>` (opens step `n` by rewriting
  `default`), `solve <n>` and `reset <n>`.

**Definition of done** is the list in `docs/AVANCEMENT.md` § « Vérifier que tout va bien ».
CI (`.github/workflows/ci.yml`) runs all of it on every branch, with the toolchain pinned
by `rust-toolchain.toml` (1.90.0, the course minimum; don't bump it without bumping
`rust-version`). It covers:

- fmt, clippy and tests for the workspace (`--workspace`, since only the root package
  builds by default);
- clippy at every step level (`--no-default-features --features stepN`, `N` = 0…13),
  which proves the `cfg_attr` guards hide nothing;
- `check-steps.sh`;
- running every example;
- fmt, clippy, tests and examples of `solutions/`;
- clippy, tests and `check-mpi.sh` for `mpi/`.

Clippy runs everywhere with `-D warnings`, examples included. Test counts drift, so do
not hard-code them.

## Step machinery

Full rules: `docs/AVANCEMENT.md` § « Conventions à respecter pour ajouter une étape » and
§ « Avertissements dans `travail/` ». The essentials:

- **Features.** Each step is a feature, chained `stepN = ["stepN-1"]`. Step N's tests are
  gated on `stepN`: unit tests in `src/`, integration tests in `tests/stepN_<topic>.rs`.
  A step-N test depends only on step-N holes, so it must be red right after `goto N`.
  Tests of older steps may turn red again at a later step that rewrites code on their
  path (AVANCEMENT, convention 2).
  **`step13` is the sentinel**: it is one past `LAST_STEP` (`xtask/src/steps.rs`,
  currently 12), gates no code, and is the default in this corrigé.
  `check-steps.sh` derives the last step from it.
- **A hole** is a `// SOLUTION-BEGIN` … `// SOLUTION-END` block:
  - It is a whole function body or a whole expression, and must typecheck as `todo!()`.
  - `// TODO-STEP:<n>` (the instruction) must sit in the contiguous comment block right
    above it. `step_of` panics otherwise.
  - An optional `// HINT :` in that same block names the Rust tool or compiler trap, with
    pseudo-code when the maths is not the point.
  - `// SOLUTION-BEGIN vide` produces an *empty* hole, for definitions. It belongs only in
    `design/`.
- **A step that rewrites working code** (for example `residual`, `write_png`,
  `check_connected`, `build_cell_faces`) gets two definitions:
  `#[cfg(not(feature = "stepN"))]` holds the old version, `#[cfg(feature = "stepN")]`
  the holed one. Otherwise `cargo run` would break in `travail/` before the step opens.
- **Warnings caused by a hole** are silenced with step-conditional attributes:
  - `#[cfg_attr(not(feature = "stepN"), allow(unused_variables))] // trou étape N` goes on
    the holed item;
  - `not(feature = "stepN+1")` goes on collateral `dead_code`;
  - if a `#[cfg]` causes the warning, gate the import instead.
- **A new step** must:
  - bump `LAST_STEP` and move the sentinel in the manifests;
  - if it adds a new crate, register it in `starter::STARTER_ENTRIES` and
    `files::SOURCE_DIRS`;
  - add `docs/etapes/etape-NN.md`;
  - be regenerated with `cargo xtask start --force`.

## Rules that are easy to break

- **Pedagogy.** A hole may only require notions taught by its date in the course calendar
  (the table in `docs/AVANCEMENT.md` § « Décisions à ne pas défaire »). Iterator adaptors
  arrive on day 3, so no earlier hole may *require* one. Each statement starts with a
  « Prérequis rustlings » line: keep it in sync.
- **Language.** Identifiers, filenames and test names are in English. Prose is in French:
  comments, doc comments, error messages, statements.
- **Trainee-facing links.** Paths in `README.md`, `ETAPES.md` and `docs/etapes/` must
  resolve both here and in `travail/`, so use root-relative paths.
- **Load-bearing design.** The rationale for each point is in AVANCEMENT § « Décisions à
  ne pas défaire ».
  - Face fluxes are `ψ(b) − ψ(a)`, which makes the divergence exactly zero for *any* ψ
    (two `1e-12` tests rely on it). Never sample the velocity at faces.
  - Walls use `ZeroGradient` with the analytic flow. `NoFlux` applies only with
    `--flow computed`.
  - The time loop stays in gather form, which is what makes `rayon` (step 9) possible.
  - `Solver::new` is generic over `StreamSource + ?Sized`. `ComputedStream` does not
    implement `VelocityField`.
  - `faer` stays an optional dependency.
  - Compare runs in physical time, never in steps. A default cap never constrains an
    explicit one (`app::caps`).
  - ParaView time comes from `frames.vtk.series`. The in-file date must sit between
    `DATASET` and `POINTS`.
  - `VtkF64` writes denormals as `0`, because VTK's ASCII reader aborts on underflow.
  - No per-value allocations in `vtk.rs`, `png.rs` or the MPI `Halo`. The remaining
    allocations in `residual`/`step_rk2` are deliberate: they are exercises.
  - The analytic flow sees an equal-area disk, not the drawn shape. This is a known
    pitfall, kept on purpose.
- **`scripts/check-steps.sh` runs `rm -rf travail`.** Never run it where `travail/` holds
  real work: use a scratch copy.
- **Workspace boundaries.** `solutions/` cannot become a workspace member: `travail/`
  receives the root `Cargo.toml` without that directory, and cargo would fail there.
  Don't make `mpi`/`design` default members.
- **Local-only files.** Files specific to one AI tool (`CLAUDE.md`, `.claude/`, `.junie/`,
  `.mcp.json`) are gitignored and never committed. `AGENTS.md` is the one shared,
  tool-agnostic agent doc; it is not shipped to `travail/`.
